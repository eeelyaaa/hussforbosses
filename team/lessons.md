# Huss for Bosses: lessons

One dated line each, one lesson per line: a playbook entry that helped or misled, a surprise from Studio, a tool or
instruction that got in the way. Suggestions for the whole team go to ro-team `vault/inbox/notes/`.

- 2026-11-25 (tech-lead, M0): the older Studio MCP's `run_code` fails with "invalid value (nil) ... for 'concat'" when `print` gets a nil argument; wrap values in `tostring`.
- 2026-11-25 (tech-lead, M0): prints from a module `require`d inside `run_code` don't come back in the `run_code` result; read them with `get_console_output`.
- 2026-11-25 (tech-lead, M0): `run_script_in_play_mode` returns only the server's log; a LocalScript's print was not in it nor in the console afterwards. Read client state through a reporting remote.
- 2026-11-25 (tech-lead, M0): DevSync works from the MCP with `HttpService.HttpEnabled` off in this place too (deja-kill's finding holds).
- 2026-11-25 (tech-lead, M1-01): in edit mode a `require`d ModuleScript stays cached after DevSync changes its Source, so a check that requires the real module reads the old version (Skins/brickbrawl came back empty). Require fresh clones; `studio/CheckSkin.lua` clones Shared + Skins together into one folder, and `Shared/Skin` finds `Skins` beside `Shared` so the clone pair stays coherent.
- 2026-11-25 (tech-lead, M1-01): `get_console_output` can be stale or truncated; to read the prints of a required `studio/` script, connect `LogService.MessageOut` inside the same `run_code`, run the script, and print the collected lines at the end.
- 2026-11-25 (tech-lead, M1-01): `run_code` while `start_stop_play` has play running still ran in the edit DataModel (`IsRunning() = false`); use `run_script_in_play_mode` for server-side play checks.
- 2026-11-25 (tech-lead, M1-01): `run_code` also fails on a boolean `print` argument ("invalid value (boolean) ... for 'concat'"), not only nil; `tostring` everything.

- 2026-11-25: Creator Hub audio upload works from the manager's Chrome at `create.roblox.com/dashboard/creations/upload?assetType=Audio&groupId=<group>`; each file needs the Audio Upload License Agreement ticked, which needs the manager's yes in chat (given for M1's 8 files). Element refs change after every page load: re-`find` after each navigate.
- 2026-11-25: The manager saw z-fighting (flicker) where the greybox floors sat 0.05 studs above the Baseplate. Check every build for coplanar or near-coplanar faces; remove or hide the Baseplate under built floors, or keep at least 0.2 studs of gap (manager: "when building check for z clipping issues").
- 2026-11-25 (animator-vfx, M1-10): `Players:CreateHumanoidModelFromDescription` R15 rigs have `AnimationConstraint` joints (no `Motor6D`), R6 have `Motor6D`; read `.Transform` on either. Pose easing uses `Enum.PoseEasingStyle` / `PoseEasingDirection` (no Quad). A `WeldConstraint` captures its offset when first parented to the workspace, so move the whole model (`PivotTo`) before parenting, not one part.
- 2026-11-25 (animator-vfx, M1-10): in edit mode `require` caches modules, so a `studio/` script that needs a file just synced requires a `:Clone()`; `get_console_output` returns the whole session (thousands of lines): have a script set its report as an attribute and `print` it from `run_code` instead.
- 2026-11-25 (animator-vfx, M1-09): in a play-mode run the first moves after start can lose frames (a 0.38 s hitch in round 1); time lengths on a second round. `print` of a boolean in `run_code` breaks the MCP's concat: use `tostring`. `Model.PrimaryPart.PivotOffset` must be set before `BossMoves` captures the rest pivot.
- 2026-11-25 (scripter, M1-06): `run_script_in_play_mode` does not return the script's `return` value (the result has no `value`); `print` the report as the last line and read it from `logs`. A server check that forges reports needs the real client quiet: the client reports a Miss on its own each ring, so disable `StarterPlayerScripts.Main` for the run and restore it.
- 2026-11-25 (scripter, M1-06): a `SetPower` while a bag burst is still running is followed by that burst's later beats (Power 25 became 29 before a fight); checks should step off the pad or wait out the burst before setting Power.
- 2026-11-25 (M1-07) In a Studio play client run through the MCP, RenderStepped fired about 6 to 12 times a second while Heartbeat fired 25 to 60: frame-time logic and test frame caps belong on Heartbeat, not RenderStepped.
- 2026-11-25 (M1-07) The Studio MCP `run_code` print capture fails on a non-string first argument ("invalid value (boolean) at index 1 in table for 'concat'"): tostring everything you print.
- 2026-11-25 (M1-07) `check_skin.py` flags any `rbxassetid://` outside Skins, so building a SoundId in a controller fails it: use `Skin.assetUrl(id)` (added by the tech-lead the same day).
- 2026-11-25 (M1-03b) A voxel boss's look is settled by fills against the picture at the picture's camera, one render per change: the first pass's boxes read as "flat box with a cap"; a brow needs to stand 2 cubes proud and step down to the centre, and the head top behind it must dip, or it reads as horns.
- 2026-11-25 (M1-03b) A wrist band on a forward-pointing glove is hidden from a front 3/4 camera; put the cuff between glove and body (glove out to the side) so both bands read in a symmetric rest pose.
- 2026-11-25 (M1-12) The sync server serves only `.lua` under `studio/`, and `run_code` returns only its own prints (nested module prints go to the console log, which is cumulative): to read a Setup script's PASS lines run it through `loadstring` with a `setfenv` that collects `print`. `check_guard.py` flags every `studio/` file without the guard, so data files carry it too.
- 2026-11-25 (M1-11) A hazard that moves as a pure function of server time needs a rest pose nobody animates: the server stamps the model's built pivot as an attribute (`TrackHome`) and clients read that, never their own (animated) pivot. Server `Humanoid:MoveTo` on a player's character does move it in Studio play mode (21.4 studs in 2 s at WalkSpeed 12), useful for speed checks without input.
- 2026-11-25: KeyframeSequences publish fastest by Explorer right-click > Save / Export > Save to Roblox (the dialog lets the creator be the group); no Animation Editor needed. `AssetService:CreateAssetAsync` answers "not available yet" from the MCP. Read a published clip back with `KeyframeSequenceProvider:GetKeyframeSequenceAsync` to check length and markers.
- 2026-11-25 (M1-14) A tagged model can reach the client before its children: a clone taken at start had no Body, and `BossMoves.loop` returned false with no warning. Wait for the whole model before taking a template, and set `PrimaryPart` on it.
- 2026-11-25 (M1-14) `BossMoves` rewrites Body.CFrame each Heartbeat from its fixed rest pivot, so anything that moves a boss (the head) must re-base the raw pose after it, in RenderStepped. A report sampled in Heartbeat sees the un-rebased pose (looked like an 11-stud error); measure after the write.
- 2026-11-25 (M1-14) Client `warn`s do not reach the Studio MCP's console tools; make the client send `Profile.TestReport` with the state (the server's log then carries it).
- 2026-11-25: The UI stud proof (StarterGui.StudProofUi) covered the manager's whole edit viewport; proof GUIs stay Enabled=false and are switched on only for a capture (manager: "can't see what's being worked on").
- 2026-11-25: In edit mode, set both `Camera.CFrame` and `Camera.Focus` from run_code, or Studio's edit camera turns the view around; ffmpeg drawtext on this PC needs `fontfile='C\:/Windows/Fonts/arialbd.ttf'` and vstack needs `inputs=N`.
- 2026-11-25 (M1-16) A server `Humanoid:MoveTo` on the player's character did nothing with the real client running (M1-11's worked before M1-14's controllers); walk a character in a check by server-side steps at the allowed speed instead.
- 2026-11-25 (M1-16) Holding a client's reports off by filling the server's rate limiter needs a refill every Heartbeat; a 0.05 s loop left a gap a real report got through.
- 2026-11-25 (M1-16) With `ReportBeats` on, the client's 0.4 s `log` reports make a 40 s play-mode call return 70 to 100 KB; turn reports on only where a check reads them, and filter the saved result for the PASS/FAIL lines.
- 2026-11-25 (M1-16) The client's clock offset after `ClockOffset` was up to 0.87 s off within 3 s of joining (GetServerTimeNow still settling); 0.03 s later in the session.

- 2026-11-25 (animator-vfx M1-20): a play-mode check must warm up about 4 s before timing a move: the first attack in a fresh session ran 1.14 s and small (frame lag). A probe that buffers reports needs a flush wait longer than buffer/rate.
- 2026-11-25 (game-designer M1-18): AutoTap `good` taps at +70 ms, which is outside the 60 ms Good window from r > 1.5, so a stand-in cannot win a fight at r >= 2 except with `perfect`; and the AutoTap hook starts a fight itself when standing in the ring, so a check that sets Power must stand outside the ring first.
- 2026-11-25 (scripter M1-26b): a camera probe that teleports the player to one tidy spot proves the frame, not the game; start the check the way a player does (walk in, press on entry, from each side) or the on-screen look finds what the probe missed.
- 2026-11-25 (scripter M1-26b): a client that saves Humanoid values to restore later must save them before the server changes them; a server freeze sent before the remote has already replicated, so "restore" wrote 0 back and the player could not walk after Run. Let the side that sets a value restore it.
- 2026-11-25 (scripter M1-26b): a Fight.Start pressed while walking into the ring reaches the server before the character does (about 2 studs behind at 16 studs/s in Studio); a server range check needs slack or the client one retry.
- 2026-11-25 (modeler M1-17): the Studio importer leaves `MeshPart.Color` at its default grey (163,162,165) and Color multiplies the texture, so a correct atlas read grey-green; set Color white (and SmoothPlastic) in the setup script after every import.
- 2026-11-25 (gui M1-15): `Enum.FontWeight.Black` does not exist; `Enum.FontWeight.Heavy` (900) selects Montserrat Black. `TextService:GetTextBoundsAsync` gave identical widths for Heavy and ExtraBold, so it is not proof of a weight: look at it.
- 2026-11-25 (gui M1-25): a viewport override in a check changes only the HUD's size; Roblox's real top bar (58 px in the Studio window) stays, so phone layouts near the top need the device emulator, not an override.
- 2026-11-25 (builder M1-05): `Workspace:Raycast` hits a part with `CanQuery = false` when `CanCollide` is on; exclude invisible blockers by name or tag in any raycast.
- 2026-11-25 (producer M1-23): a gate that passes by script still left 11 looks unseen and the three failures the main session did catch (HUD under the top bar, RUN on a plate, the avatar hiding the frog) were all invisible to probes; plan the on-screen list with the build and run it as each wave lands, not at the end.
- 2026-11-25 (producer M1-23): an evidence file written by an early run (`m1-checkall.md`, 2 FAIL) goes stale when later tasks fix its failures; mark it superseded and point at the latest run, or the close-out reads a FAIL that is gone.
